# 🏛️ Campus BGPU — Сервис бронирования ресурсов кампуса

Бэкенд-система управления и поминутного бронирования оборудования кампуса (прачечные, коворкинги, учебные аудитории) с интеграцией внешней аутентификации и защитой от конфликтов расписания.

---

## 🛠 Технологический стек

* **Язык и среда:** Kotlin 2.1, Java 21, Spring Boot 3.3.4
* **Безопасность:** Spring Security 6, JWT, Stateless сессии
* **Базы данных и миграции:** PostgreSQL 16, Flyway, Spring Data JPA, H2 (для тестов)
* **Тестирование:** JUnit 5, RestAssured (MockMvc), MockK, Mockito
* **Инфраструктура и API:** Docker, Docker Compose, SpringDoc OpenAPI (Swagger 3.0), GitHub Actions

---

## 🚀 Ключевые инженерные решения

1. **Двухуровневая защита от состояния гонки (Race Condition):**
   * Валидация временных нахлестов в сервисном слое.
   * Контроль на уровне ядра СУБД через расширение `btree_gist` и констрейнт `EXCLUDE USING gist` (аппаратная невозможность двойного бронирования одного слота).
2. **Динамическая генерация сетки слотов:**
   * Суточное расписание (24 часа) нарезается «на лету» в памяти по запросу, без засорения БД фиктивными строками.
3. **Модель допуска (Gatekeeper):**
   * Студент может бронировать ресурсы только в тех корпусах, куда у него есть официальный цифровой пропуск.
4. **Автоматическое завершение сессий:**
   * Фоновый планировщик (`@Scheduled`) пакетно переводит истекшие бронирования в статус `COMPLETED` одним оптимизированным SQL-запросом.

## 🧪 Пирамида автоматизированного тестирования

В проекте реализовано 3 уровня тестирования:

| Уровень | Инструменты | Что проверяется |
| :--- | :--- | :--- |
| **Unit-тесты** | JUnit 5, MockK | Бизнес-правила бронирования, нарезка суточных слотов, валидация прав доступа к комнатам. |
| **Интеграционные тесты БД** | `@DataJpaTest`, H2, Hibernate | Кастомные JPQL/SQL-запросы, пограничные условия интервалов времени (`existsOverlap`), пакетные апдейты. |
| **Контрактные API-тесты** | RestAssured (MockMvc), Spring Security Test | Валидация входных DTO (HTTP 400), сквозной Happy Path (HTTP 200 + JSON), безопасность закрытых URL (HTTP 403). |
